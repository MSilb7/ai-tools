**Background:** A Hermes agent reported reading full X threads with no credentials and attributed
the capability to its managed web-extraction backend (Firecrawl-style). Validated live from a bare
container: the backend attribution is wrong — plain unauthenticated HTTP suffices. Five no-auth
read paths confirmed working: fxtwitter/vxtwitter JSON APIs, the server-rendered x.com status page
(post text in `og:description` plus every visible conversation status id embedded in the markup —
the key to thread reconstruction), the syndication CDN (`tweet-result?id=…&token=a`, any short
token accepted), oEmbed, and the syndication timeline endpoint (~100 recent posts per user).
Non-obvious walls found during validation: the timeline endpoint 429s after a couple of requests
per IP (transient, not a login wall), and early tweet ids are short (jack's is literally `20`), so
id-shaped regexes must not assume snowflake length. Node 22 `fetch` ignores proxy env vars and CA
bundles, so the bundled script uses curl for transport.

**Goal:** Every agent reads public X posts/threads/timelines via the documented no-auth recipe
instead of assuming X is login-walled or asking the user to paste.
